# 日报周报生成工具

---

## 一、首次运行：配置检查

配置文件：`./config/config.json`（相对于本 skill 目录）

**如果该文件不存在，立即停止，不要执行任何命令，向用户输出以下内容：**

```
⚠️ 还没有配置，先完成配置再生成日报

1. 复制 skill 目录下 example 里的 样例配置.json，改名为 config.json 放到 config 目录下
   config/config.json

2. 打开后修改两处：
   - author_name：改成你的 Git 提交人用户名
   - projects：改成你要统计的模块名和对应仓库路径
     （模块名就是以后说"某某的日报"里的"某某"，Windows 路径要写成双反斜杠）

配置完成后重新告诉我即可。
```

配置存在时，读取其中的 `author_name` 与 `projects` 的键（模块名），进入下一步。

---

## 二、用户怎么调用

用户会用下面这类话触发（说日报还是周报都一样，**都同时产出日报 + 周报**）：

- 编写项目管理的日报 / 生成项目管理的周报
- 编写项目管理7月8日后的日报
- 生成项目管理7月8日到7月10日的日报

把用户说的"项目名/模块"对应到配置里 `projects` 的某个键：

- 能匹配上就用这个键（允许忽略大小写、首尾空格）
- 只有一个模块且匹配不上，直接用这个唯一模块
- 有多个模块又匹配不上，**列出可用模块让用户选，不要猜**

用户没说日期 → 默认近 7 天；说了日期 → 按用户给的起始日期。

---

## 三、执行方式（唯一允许的取数途径）

**只能用脚本取 Git 数据。禁止自行执行任何 git 命令（git log、git show、git branch 等一律不许），禁止编造或推测提交记录。**

命令格式：

```bash
python GetPrjGitRecords.py -a config/config.json -b <模块名> -s <YYYY-MM-DD>
```

- `-a`：配置文件路径，必填
- `-b`：模块名，即配置中 `projects` 的键，**必填**；不传会直接报错，也不能省略成"统计全部"
- `-s`：起始日期（YYYY-MM-DD），不填默认 7 天前；用户没说日期就不要传

> `-s _` 是给人手动运行时的交互输入占位符，AI 调用时不要用，直接传具体日期。

日期换算：用户说"7月8日后" → `-s 2026-07-08`（年份取当前年）。

脚本执行后会：控制台打印提交记录，并在桌面 `日报YYYYMMDD/` 文件夹生成 `{模块名}(起始-结束)提交记录_结果.txt`。

**若脚本无法执行**（Python 不存在、git 不可用、脚本报错、找不到配置文件等环境问题）：**立即停止**，把报错信息原样告诉用户并说明卡在哪一步，等用户处理。不允许绕开脚本用 git 命令顶替，也不允许凭印象编造记录。

## 四、生成日报的提示词

基于脚本输出的提交记录，撰写每日工作日报和本周工作周报。

**要求：**

1. 必须使用 Markdown 有序列表格式 `1. 2. 3.`
2. 按日期分段，每天单独一段，无提交记录的日期注明"无提交记录"
3. 每条事项用序号列出，语言简洁专业，每条不少于 20 字
4. 不要出现仓库名称，只描述实际完成的工作内容
5. 合并同类项，避免重复罗列
6. 周报"本周工作总结"用有序列表，每条格式为"**主题**：具体内容"
7. 周报需包含"下周工作计划"章节

**输出格式：**

```markdown
# 每日工作日报

**项目：xxx**
**统计周期：2026-07-03 ~ 2026-07-10**
**提交人：xxx**

## 2026-07-03

1. 第一条工作内容
2. 第二条工作内容

## 2026-07-04

1. 无提交记录
```

```markdown
# 本周工作周报

## 本周工作总结

1. **主题一**：具体内容描述

## 下周工作计划

1. 下周计划一
```

**存放位置：** 与提交记录放在同一个桌面 `日报YYYYMMDD/` 文件夹，文件名为 `{项目名}_日报周报_{起始日期}-{结束日期}.md`。
